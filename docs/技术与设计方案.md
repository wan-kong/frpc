# frp-desktop 技术与设计方案

日期：2026-11-05；实施说明更新于 2026-11-06。状态：已进入实施，当前完成情况与验证边界见《实施进度》。

本文的版本、功能和 API 判断基于当前目录及实际依赖源码；性能数字是验收目标，不是已测结果。

## 1. 产品方向与关键决策

做一款面向开发者、运维和个人服务使用者的 macOS frp 客户端工具。用户已有 frps 地址和凭证，在本机创建连接、配置隧道、运行 frpc，并能快速判断连接出了什么问题。

推荐采用 **MyGo 0.7.4 + `ui` Native UI + 独立 frpc 子进程 + macOS 系统集成**。主界面、设置和更新窗口全部使用 Go Native UI。首个正式版本支持 macOS 13 及以上，提供 Apple Silicon 和 Intel 两个独立安装包，优先验收 Apple Silicon。

五项决定：

1. **以连接配置为核心。** 一份连接配置绑定一个 frps 端点、一组代理/访问者、一个明确的 frpc 版本和一个独立进程。多个连接可以同时运行。
2. **以原生工具的工作方式组织界面。** 来源列表、工具栏、隧道列表、详情检查器和日志区域构成主窗口；系统菜单和菜单栏图标提供辅助入口。
3. **分别管理用户意图与实际状态。** 已保存、待应用、正在连接、代理注册成功、业务可达是不同事实，不合并成一个绿色开关。
4. **应用和内核分别更新。** 应用使用 MyGo 自带签名 updater；内核按连接固定版本，只有用户主动选择才切换。
5. **配置变更可解释、可恢复。** 保存前检查，应用前说明影响，失败后保留编辑内容和上一份有效配置。

最小可用范围：单连接、多条 TCP/UDP 隧道、启动/停止、真实状态、日志、TOML 导入、签名应用更新。这也是第一阶段可独立交付的版本。完整首版在此基础上增加多连接、HTTP/HTTPS、私密代理及访问者、内核版本管理和备份。

### 1.1 Native UI 的准确边界

MyGo 的 `ui` 是 Go 驱动、GPU 绘制的组件体系，macOS 使用 Metal；它不是 AppKit 的 NSButton、NSTableView，也不是 SwiftUI。系统窗口、菜单、文件选择器和登录项等使用 MyGo 的桌面 API；凭证不经过系统 Keychain。

本文将“符合 macOS”定义为窗口行为、信息结构、键盘操作、系统外观和辅助功能符合用户习惯。若产品要求每个表单控件都是 AppKit 原生对象，本方案不能满足，需要重新选择 UI 技术。当前按用户指定的 MyGo Native UI 路线设计。

## 3. 功能范围与协议

### 3.1 完整首版范围

- 连接：新建、复制、重命名、分组、排序、搜索、独立运行、批量启动/停止。
- 身份：token、user、metadata；TLS 和到 frps 的传输参数在高级设置中管理。
- 隧道：TCP、UDP、HTTP、HTTPS、STCP、SUDP、XTCP；STCP/SUDP/XTCP 包含访问者配置。
- 常用字段：本地地址/端口、远程端口、域名/子域名、HTTP 路径和认证、压缩/加密等按固定内核能力展示。
- 批量端口：相同长度的本地/远程范围展开成独立条目；冲突时在预览阶段指出具体条目。
- 日志：按连接、隧道关联、等级、时间和文本过滤；暂停跟随、复制、脱敏导出。
- 配置：TOML 导入、可视化编辑、受控的原文模式、配置预览、备份/恢复。
- 运行：菜单栏操作、关闭窗口后继续运行、登录启动、每连接自动连接。
- 更新：签名应用更新、独立内核下载与切换、离线保底内核。

不纳入完整首版：frps 管理、远程 SSH、云账号、配置云同步、公共节点市场、移动端、Windows/Linux 成品、后台系统守护服务、VirtualNet/TUN、任意插件的可视化表单、全版本兼容承诺、YAML/JSON/INI 转换器。访问已有 frps 及 frpc 本机管理 API 均属于客户端能力。

### 3.2 版本策略

检索时 frp 最新稳定 release 为 [v0.72.0](https://github.com/fatedier/frp/releases/tag/v0.72.0)。将其作为初始认证内核与随应用分发的保底版本，发布前必须完成本文的协议检查。frps 是否兼容取决于用户的服务端版本，不能因是最新内核就默认升级所有连接。

版本分三个等级：

| 等级                          | 行为                                                                              |
| ----------------------------- | --------------------------------------------------------------------------------- |
| 已认证版本                    | 有明确字段能力表、状态 API 适配和 CLI 集成检查，开放受支持的完整可视化能力        |
| 其他现代版本                  | 允许用户导入/选择，先检查版本和 verify 命令；只允许原文运行，不承诺重载与状态兼容 |
| 不具备安全启动/验证契约的版本 | 阻止启动，保留原文件，说明需要的内核能力；不静默降级严格校验                      |

“下载成功”与“已认证兼容”分开显示。每个版本的能力记录包含：支持格式、协议字段、verify 命令、reload 能力、管理 API schema、已验证的操作系统/架构。新版本不会自动变成已认证版本。

## 4. 信息架构与窗口设计

视觉方向：克制的 macOS 网络工具。使用系统字体、系统强调色、清晰的列表与分栏；侧栏可使用系统材质，工作区保持不透明，减少视觉噪声。设计识别点是隧道列表中稳定对齐的“本地端点 → 远程端点”和始终可解释的状态。

交互方向：先看清连接状态，再操作隧道，故障信息与受影响对象相邻。输入、切换选择和查看日志不触发网络变更。

### 4.1 主窗口

默认 1120 × 760 DIP，最小 900 × 600 DIP；使用系统标题栏按钮，保留全屏、缩放、拖动和多显示器行为。隐藏标题栏背景可以用于工具栏融合，但不自绘红黄绿按钮。

```text
┌───────────────────────────────────────────────────────────────────────┐
│ ● ● ●   办公网络                  搜索隧道     ＋     连接 / 停止     │
├──────────────────┬────────────────────────────────────────────────────┤
│ 全部连接         │ 办公网络                         3 个已注册 / 1 故障│
│ 需要关注    1    │ frp.example.net:7000       内核 0.72.0    运行中    │
│                  ├────────────────────────────────────────────────────┤
│ 工作             │ 隧道          访问者          连接设置              │
│   办公网络   ●   ├───────────────────────────┬────────────────────────┤
│   测试环境   ○   │ 名称  协议  本地 → 远程   │ 隧道详情               │
│                  │ ssh   TCP   :22 → :6022   │ 本地地址 127.0.0.1     │
│ 个人             │ web   HTTP  :3000 → 域名  │ 远程端口 6022          │
│   家中设备   ●   │ ...                       │ 状态：已注册            │
│                  │                           │ [编辑…] [复制地址]      │
├──────────────────┤                           │                        │
│ 内核             ├───────────────────────────┴────────────────────────┤
│                  │ 日志    等级  搜索    暂停跟随     导出             │
│                  │ 14:32:08  ssh  注册失败：远程端口已被占用           │
└──────────────────┴────────────────────────────────────────────────────┘
```

示例内容仅用于描述布局，不代表真实连接。

- 侧栏宽 220 DIP，可在 190–300 间拖动。底部只保留“内核”；设置放在应用菜单中。
- 隧道列表是主要工作区，默认列为启用、名称、协议、本地、远程、状态。端点使用等宽字体；复制完整值不依赖可见截断文本。
- 详情检查器默认宽 300 DIP，可收起；窗口小于 1040 DIP 时默认收起，通过工具栏或快捷键打开。
- 日志默认收起；故障时出现一行问题摘要及“查看日志”，不自动抢占焦点。展开高度默认 220 DIP，可拖动。
- “全部连接”显示跨连接的紧凑隧道表；“需要关注”只显示失败、持续重连、待应用和状态不可用的对象。
- 单击选择和查看，双击编辑；多选支持统一启用/禁用、移动和删除。批量操作显示影响条目数量。

## 5. 核心交互规则

### 5.1 创建与首次连接

1. 填写连接名称、frps 地址、端口和凭证；默认选择随包认证内核。
2. 连接端口默认 7000，本地地址默认 127.0.0.1；这些是本产品新建表单默认值，不覆盖导入文件中的明确值。
3. 提供“添加第一条隧道”，可跳过。只有公共配置时也可以启动，但不能据此宣称隧道可用。
4. 保存运行前先严格校验配置；“连接”后展示连接中、实际代理状态与错误原因。
5. 地址连通检查只表达 TCP/DNS 测试结果，不冒充 frp 认证成功。

新建连接默认开启到 frps 的 TLS；在认证内核支持的字段能力内启用系统 CA/指定 CA 的服务端身份校验，IP 地址与证书名称不匹配时给出具体原因。导入配置保留其明确选择，关闭证书校验或 TLS 时在连接设置中持续显示风险说明，不自动改写为不同的连接策略。

### 5.2 编辑、保存和应用

编辑在独立草稿中进行。关闭 sheet 时仅在有修改时提示“保留草稿 / 放弃 / 继续编辑”。保存成功保留配置，应用失败不清空草稿或丢失已保存版本。

| 变更                                    | 运行中如何应用                        | 用户看到的说明                            |
| --------------------------------------- | ------------------------------------- | ----------------------------------------- |
| 名称、分组、显示排序                    | 本地即时保存                          | 不影响连接                                |
| 代理配置、单隧道启停                    | 已认证版本生成配置后 reload，再读状态 | “正在应用”；完成后显示真实注册结果        |
| frps 地址、认证、传输参数、管理监听配置 | 重启该连接的 frpc                     | “需要重新连接，将中断此连接下的 N 条隧道” |
| 内核版本                                | 用目标版本 verify 后重启该连接        | 显示版本变更及影响；失败可回退            |
| 原文模式配置                            | 整个连接重启                          | 不承诺字段级热更新                        |

对访问者变更按版本能力执行；只有通过集成检查后才允许热更新，否则统一提示重启。端口、域名变化可能影响现有会话，不能笼统宣称 reload 无中断。

快速单隧道开关是明确的应用动作：立即更新期望状态，进入“应用中”，成功后同步实际状态。失败显示“未应用”并提供重试/恢复，不能让开关与后台状态悄悄分离。连续操作合并为 250ms 内的一次应用，同连接仍严格串行。

### 5.3 状态语义

分开记录和展示三层状态：

- 进程：已停止、启动中、运行中、停止中、异常退出。
- 与 frps 的会话：连接中、已连接、重连中、认证失败、未知；已连接只能来自明确证据，不能来自 PID 或本机管理 API 的 HTTP 200。
- 隧道：停用、待应用、注册中、已注册、注册失败、状态未知；业务服务是否可用另行检测。

v0.72.0 `/api/status` 提供代理状态，不提供完整控制会话状态或统一 visitor 运行状态。无代理、API 缺失或证据过期时显示“进程运行中，连接状态未确认”。会话日志适配只能作为补充证据，断网/重连事件必须使旧的成功证据失效；任何状态超过 10 秒未更新都加“状态已过期”。

“本地服务检测”是用户主动动作：TCP 建连成功表示端口可连接；UDP 不用 TCP 探测，也不把未收到响应直接判为失败。未做外部端到端探测时，不能将“代理已注册”改称“外网访问正常”。

### 5.4 失败、删除和退出

- DNS、认证、端口占用、配置错误、内核缺失、配置文件损坏和权限错误都显示具体对象、原因及下一步动作。
- 删除运行中的连接先说明会停止的隧道；连接先移入本地回收区 7 天，密钥到期后删除。撤销恢复配置，不自动恢复运行。
- 删除运行中的隧道会应用新配置，需要显示实际失败情况；删除内核时若仍被连接或待回滚版本引用则阻止。
- 点击红色关闭按钮或 `⌘W` 隐藏主窗口，frpc 继续运行；首次隐藏时提示一次，可从菜单栏或 Dock 重开。
- `⌘Q` 表示退出应用并停止所有受管 frpc。存在运行连接时给出明确确认，允许记住选择；系统注销/关机走有时限清理，不等待交互弹窗。
- 睡眠时不强制阻止系统睡眠。唤醒后先核对现有进程，等待 frpc 自身重连；不盲目另起进程。
- “登录时启动”和“启动后自动连接此配置”是两个独立设置，默认均关闭。登录启动默认不弹主窗口。

## 6. 技术架构

采用单应用进程、多个受管 frpc 子进程。首版不增加独立常驻 daemon、Web 服务、数据库服务或 Rust/Swift 工程。

```text
MyGo UI / 菜单 / 菜单栏
          │ commands                 ▲ 不可变快照 / 有界事件
          ▼                          │
      AppController ─────────────────┘
       │       │             │
       │       │             └── AppUpdate（mygo.Updater）
       │       └── CoreCatalog / Downloader
       ├── Repository ── 本地 config.json（含凭证）
       └── Supervisor（每连接串行队列）
                 ├── ConfigCompiler / Verifier
                 ├── ExecRunner ── frpc 子进程
                 ├── AdminClient ── 127.0.0.1 管理 API
                 └── LogPipeline ── 有界内存缓冲 / 轮转文件
```

依赖单向流动：UI 不直接写文件或操作进程；domain 不依赖 MyGo；infra 不回调 UI。Supervisor 对外发布快照，UI 通过主线程投递更新读取快照。

### 6.1 模块和文件边界

预计超过 8 个文件，属于完整应用建设；按以下包划分，避免把全部逻辑放进 main.go。

| 路径                   | 职责                                                             |
| ---------------------- | ---------------------------------------------------------------- |
| `main.go`、`mygo.json` | 初始化、系统身份、窗口与插件、打包元数据                         |

| `internal/config/`     | TOML 解析、能力验证、生成、语义 diff、脱敏                       |
| `internal/runtime/`    | Supervisor、进程运行、管理 API、状态聚合、重连策略               |
| `internal/storage/`    | JSON 仓储、schema migration、备份、恢复、SecretStore             |
| `internal/core/`       | 内核目录、下载、校验、架构检查、版本与能力表                     |
| `internal/platform/`   | 登录项、单实例、菜单栏、进程组和受管进程回收                     |

### 6.2 核心数据模型

| 实体            | 关键字段                                                                                                                                |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Profile         | id、revision、name、group、mode、serverAddr、serverPort、user、metadata、authSecretRef、transport、tls、coreVersionID、autoConnect      |
| Tunnel          | id、profileID、name、type、enabled、localEndpoint、协议专属字段、secretRefs、sortOrder                                                  |
| Visitor         | id、profileID、name、type、serverName、serverUser、secretRef、bindAddr、bindPort、enabled                                               |
| CoreVersion     | id、version、platform、arch、path、sourceURL、sha256、certification、capabilities                                                       |
| RuntimeSnapshot | profileID、generation、desiredRunState、processState、sessionState、PID、startedAt、appliedRevision、proxyStates、lastObservedAt、error |
| Draft           | ownerWindow、profileID、baseRevision、编辑内容、dirty、validationErrors                                                                 |
| Operation       | id、profileID、generation、type、phase、startedAt、cancelable、error                                                                    |

ID 为随机稳定标识，名称可变。协议字段用带类型的联合结构，不使用一个塞满互斥字段的通用 map。`revision` 做乐观并发检查；不同编辑窗口不能直接覆盖彼此。PID、端口和运行状态不作为下次启动的真实状态保存。

### 6.3 命令契约

内部应用命令固定为：CreateProfile、SaveProfileDraft、DeleteProfile、ImportTOML、ExportProfile、StartProfile、StopProfile、ApplyProfile、SetTunnelEnabled、InstallCore、SwitchCore、ExportDiagnostics。

每个修改命令携带 profileID、期望 revision 和 operationID；重复 operationID 不重复执行。执行返回成功快照或结构化错误：code、message、fieldPath、retryable、cause；错误码至少区分 Validation、Conflict、SecretUnavailable、BinaryMissing、PortInUse、StartFailed、AdminUnavailable、ApplyFailed、DownloadFailed、ChecksumMismatch、PermissionDenied。

没有对外 HTTP API；Go UI 直接调用 controller。未来跨平台 UI 或远程控制不成为首版依赖。

## 7. MyGo UI 生命周期与并发

- `App.Run` 在主 goroutine；视图和菜单回调只做短操作。
- 慢 I/O、verify、网络、进程等待与日志解析放到 worker。后台结果通过 `Window.Update` 投递到 UI 状态；`Invalidate` 仅用于重绘，不能代替并发同步。
- 仓储和 Supervisor 通过自己的队列/锁维护状态；向窗口发布不可变快照，不共享可变 slice/map。
- 列表使用稳定 ID 作为 `ItemKey`；组件使用稳定 Key 和 `ui.Handle`。不在状态或 goroutine 中保存 `ui.Element`、custom parts 或 `*ui.Context`。
- 隐藏主窗口保留草稿和 Supervisor，停止隐藏列表的增量刷新，再次显示时从快照恢复。窗口真正销毁时取消视图任务并解除订阅。异步结果同时检查窗口生命周期 token 和 operation generation，过期结果直接丢弃。
- 同连接 Start、Stop、Apply、SwitchCore 串行；不同连接并行，批量启动并发上限 4。
- 不在 view 重建、绘制或布局函数中触发下载、写文件、启动进程和通知。
- 日志以 50–100ms 批次通知 UI；网络状态低频更新，隐藏窗口不做表格刷新。空闲界面不运行人为的逐帧计时器。

## 8. 配置、数据与凭证

### 8.1 持久化

首版采用版本化 JSON 文件与原子替换，不引入 SQLite。连接数量有限，过滤在内存完成；追加日志不进入配置文件。

数据目录固定为用户主目录下的 `~/.frpc`，不依赖 MyGo 的用户数据目录；日志仍走平台日志路径。逻辑组织：

```text
~/.frpc/
  config.json                  # schemaVersion、profiles、tunnels、visitors、settings、secrets
  cores/index.json             # 安装版本、摘要、能力与引用
  cores/<version>/<arch>/frpc   # 用户下载的不可变内核
  sources/<profile-id>.enc     # 原文模式的加密源文件
  backups/                     # 最近 10 份 config.json 快照（含凭证，0600）
  trash/                       # 7 天回收区
  runtime/<profile-id>/         # active、candidate、previous 配置及所有权记录
```

目录权限 0700，含敏感内容的文件 0600。写入使用同目录临时文件、flush/fsync、rename；成功后递增 revision。存储错误时不能显示“已保存”。schema migration 先备份再迁移，失败不写回；禁止直接覆盖未知更高 schemaVersion 的文件。

### 8.2 密钥策略

不使用系统 Keychain。token、私密代理密钥、metadata 值和管理 API 随机密码以 base64 形式保存在 `config.json` 的 `secrets` 字段中，Profile 仍只保存 SecretRef；文件权限为 0600。更新已有凭证先写新条目，再提交 state，最后回收旧引用；崩溃后可清理未引用条目，不能先删旧凭证。

原文模式可能含未识别的敏感字段，因此整份源文件用 AES-256-GCM 加密，随机 nonce，每份文件包含格式版本；主密钥作为普通条目保存在同一个 `config.json`。它避免 `sources/` 中的原文被直接读取，但不构成针对可访问该目录的本机用户的额外保护；原文编辑前必须能取到主密钥，失败时不降级为明文存储。普通可视化数据中非敏感字段仍保持可诊断性。

frpc 需要读取明文运行配置：仅在受保护 runtime 目录生成，停止后清理；这不等于运行时凭证零落盘。异常退出可能残留，启动时在确认对应进程已结束后清理。日志先脱敏再写盘，密码不放命令行，不打印完整环境。

### 8.3 可视化模式和原文模式

可视化模式只维护已支持 schema，确定性生成 TOML；GUI 数据是唯一编辑来源，生成文件不供外部直接修改。

导入先解析预览：地址、隧道数量、协议、敏感字段和不支持项，用户确认后复制进应用自己的数据存储。原文件不覆盖。字段全部可表达时转为可视化模式；发现未知字段时，允许以原文模式保留，不做会丢字段的强制转换。

原文模式可编辑文本并由选定内核 verify，但不开放单隧道开关和字段级热重载。保留原文和注释，不与表单互相覆盖。首版只接受自包含 TOML：遇到 includes、环境模板、外部证书/插件路径时阻止导入，并逐项说明需要先合并配置或将资源纳入受管附件；首版不偷偷读取外部路径或继承用户 shell 环境。可视化模式的 TLS 文件通过显式文件选择复制为受管附件。

普通配置导出默认省略 secret 值并清晰标记“需补充凭证，不能直接运行”；用户选择“包含凭证”才输出可运行 TOML，并在文件面板前明确包含明文。完整备份使用单一加密归档，包含 schema、配置、受管附件和凭证；AES-GCM 密钥由用户口令通过 scrypt 派生，参数及随机盐记录于包头，口令不保存。还原先验证归档大小/路径、解密与 schema，再预览合并；新 ID 导入，名称冲突显示重命名建议，默认不自动启动。

## 9. frpc 运行、控制和恢复

### 9.1 进程管理

不嵌入 frp Go 内部包，使用可替换的官方 frpc 可执行文件。这样避免客户端内部 API 漂移牵连 UI，也能让连接保留兼容的旧版本。

- 固定绝对路径，使用 `exec.Command` 的参数数组启动 `frpc -c <path>`，不经 shell，不接受额外任意命令片段。
- 启动顺序：检查内核与架构 → 解析密钥 → 选择管理端口及认证信息 → 编译 candidate → `frpc verify -c <candidate>` → 写 active → 启动并观察状态。端口竞争后的重试重新生成并验证配置。
- 每连接独立工作目录、进程组、generation 和随机所有权 token。stdout/stderr 持续排空；等待退出只由一个 owner 负责。
- 先请求正常停止或发送 SIGTERM，最多等待 5 秒，再对确认属于该连接的进程组 SIGKILL；只有 wait 完成才标为已停止。
- 父应用另带内部 `--frpc-session` 运行模式作为轻量看护进程：为 Supervisor 持有 frpc、监听父子控制管道，收到父进程管道 EOF 时终止并回收 frpc。它不是另一个常驻服务，不注册 launchd，也不提供网络接口。
- 看护进程也可能异常：主应用启动时只依据受保护的运行记录、PID 启动时间、可执行路径及含随机 token 的运行目录核对残留。身份不完整时显示“发现未确认进程”，不按名称批量杀进程或只凭旧 PID 操作。
- 单实例锁由 MyGo 提供，第二次启动聚焦已有窗口，避免重复管理同一份配置。

### 9.2 管理 API 和状态来源

已认证版本由应用生成 `webServer.addr = 127.0.0.1`、独立管理端口及随机用户/密码，不对局域网开放，不复用 frps token。管理端口先选取可用端口，启动时仍可能有竞争；发生监听冲突时最多重选 3 次，随后显示失败，不能把启动前探测当成端口预留。

AdminClient 是版本化 HTTP 适配器，固定访问本机当前运行实例，使用认证、超时和响应大小限制，不跟随重定向。不使用 frps Dashboard API。

- v0.72.0：读取 `GET /api/status`，重载调用 `GET /api/reload?strictConfig=true`，停止可用 `POST /api/stop`；以已读取源码为依据。
- 不开放不必要的 `/api/config` 编辑或新 store API，应用自己的配置事务保持唯一入口。
- 只展示 API 实际提供的数据；不承诺 v0.72.0 status 有每隧道流量、带宽或 visitor 会话指标。
- 前台当前连接每 2 秒观察一次，非当前运行连接每 5 秒，所有窗口隐藏后每 10 秒；可合并批次，不为每条隧道开一个定时器。
- 原文模式不注入/覆盖用户的 webServer，首版只显示进程和有限日志证据，状态能力明确标记为受限。

### 9.3 应用事务与回滚

1. 保存配置意图到新 revision，生成 candidate，并用当前内核严格 verify；校验失败不替换 active。
2. 将当前 active 保留为 previous，原子替换 active 为 candidate。
3. 调用重载或重启，根据变更种类执行；请求成功后继续观察代理状态。
4. reload HTTP 成功不等于全部隧道注册成功。默认观察窗口 15 秒；未决条目标为待确认/超时，允许继续观察。
5. 只有请求/解析/进程级失败才自动恢复 previous 并尝试恢复一次；部分代理注册失败只标明具体失败对象，不自动撤销全部变更。
6. 恢复也失败时保留两个版本和错误，明确显示“恢复失败”；不循环重启。重新加载旧配置也不能保证已有业务会话恢复。

savedRevision 和 appliedRevision 分开保存，保证“已保存但未应用”可见。应用期间用户继续编辑产生更新 revision，旧请求不能覆盖新草稿；操作结束后再提示应用新版本。

### 9.4 重连与重启

frpc 自身负责会话重连；Supervisor 只重启退出的进程，不能因 API 一次超时就重复启动。可视化生成配置采用允许持续重连的登录策略，认证错误时显示可恢复的明确错误。

异常退出的重启间隔为 1、2、4、8、16、30 秒，带随机抖动；5 分钟内失败 5 次进入熔断，要求用户手动重试或修改配置。正常运行 5 分钟后清空失败计数。手动停止、应用退出和系统睡眠不累计失败次数。

## 10. 日志、性能与可访问性

### 10.1 日志

每连接内存最多保存 10,000 行且不超过 8MiB，先达到哪个上限就淘汰最旧行；单行最多读取 64KiB，超长内容标记截断并继续排空，不能让 pipe 阻塞 frpc。磁盘每连接 5 个 5MiB 轮转文件，总配额 250MiB，超额删除最旧非当前文件。

正文脱敏覆盖已知 secret 值、认证头、URL userinfo 和常见敏感字段；没有办法保证任意第三方错误文本百分百可脱敏，因此导出前提供预览和“已自动隐藏已知凭证”的准确说明。暂停跟随不停止采集；恢复跟随跳至最新位置。搜索做 150ms 防抖，支持中文，不对全量日志每帧重新过滤。

### 10.2 性能验收目标

在 Apple Silicon、macOS 13+，20 个配置、10 个同时运行连接、总计 500 条隧道、当前连接 100 行/秒日志的基准下：

| 指标        | 目标及口径                                                                      |
| ----------- | ------------------------------------------------------------------------------- |
| 窗口可交互  | 进程启动至首个可输入视图，p95 ≤ 800ms，不包含 frps 网络连接                     |
| UI 输入反馈 | controller/UI 更新 p95 ≤ 50ms；I/O 完成时间独立记录                             |
| UI 帧耗时   | CLI Tester 中布局/构建 p95 ≤ 16ms；不把它当作真实 Metal 流畅度证明              |
| 空闲负载    | 无动画、无日志增量时不持续重建 UI；CLI CPU profile 排除人为忙循环               |
| 内存        | UI 日志缓冲始终受配额限制，连续负载 30 分钟无持续增长；主应用与各 frpc 分开计量 |
| 退出        | 正常受管进程 5 秒内结束，超时进程进入有界强制清理                               |

列表和日志使用 MyGo 的可见行构建能力，500/5,000 条目都做基准。10 倍规模下首先限制刷新与日志总量，不承诺同时运行 100 个 frpc 的资源开销；内核独立进程本身有成本。

### 10.3 可访问性

所有图标动作有名称，状态附文本，完整 Tab/Shift-Tab 操作，焦点清晰；sheet 关闭后恢复触发控件焦点。中文输入组合期间不触发提交，支持中英文混合长名称、IPv6、长域名和显示缩放。优先用框架控件提供的辅助功能节点，Tester 验证标签与焦点，不将其表述为已完成 VoiceOver 真人验收。

## 11. 应用更新与内核分发

### 11.1 应用 updater

初始方案评估了 MyGo v0.7.4 的 `github.com/egoist/mygo/plugins/updater/native`。该插件的重启动作直接调用 `mygo.App.Relaunch`，与本产品必须先停止连接并写入一次性 resume 的退出协调器冲突，因此不启用插件，也不维护自建更新状态机：检查和安装直接调用 `mygo.Updater`，只保留一个薄 Native UI 面板。不引入 Sparkle 桥接、WebView 或自建更新源。

- `mygo.json` 的 `updates.publicKey` 和 `updates.github` 固定更新公钥和本产品的公开发布仓库；GitHub Releases 稳定版 tag 使用 `v<semver>`。
- 只提供手动检查：菜单和设置面板调用 `mygo.Updater.Check`，明确显示检查中、已是最新、失败或不可自更新的原因。
- 安装使用 `mygo.Updater.Install`，显示下载进度；成功后用户可关闭面板让更新在下次启动生效，或立即走统一退出协调器重启并恢复连接。不做后台轮询、跳过版本或更新偏好持久化。
- 下载、签名验证和替换由 MyGo 负责；文件损坏、签名不符、离线、代理错误和安装目录不可写都不能影响当前 frpc。
- 开发模式或不可自更新安装位置显示能力不可用及原因，不伪造“已是最新版本”。

更新重启接入统一退出协调器：`OnBeforeQuit` 中存在运行连接时，先阻止退出并给出“重启应用将中断 N 个连接”的确认；确认后异步停止全部连接，写入一次性、短时有效的 resume 记录，再允许 Relaunch。普通 `⌘Q` 不写 resume。新版本启动仅消费一次该记录，恢复更新前确实运行的配置；应用更新不会改变它们的 coreVersionID。

MyGo 的替换更新不提供本产品业务级启动失败自动回滚承诺。每次 schema migration 前留兼容备份，保留上一版安装包下载入口；用户回退应用时恢复对应 schema 备份，不让旧版本直接写新格式。新版本根本未启动时，resume 记录不会自行重启进程，界面文案需如实说明短暂中断及失败后的恢复方式。

### 11.2 frpc 内核

- 初始安装包附带认证版 frpc，离线即可建连接。按 `resources/darwin-arm64/`、`resources/darwin-amd64/` 分发，通过 MyGo 的资源规则只包含目标架构。
- 额外内核从 `fatedier/frp` 官方 Release 获取，选择当前系统/架构资产，以官方 checksum 和 Release digest 核验；没有可信摘要时拒绝自动安装。
- 摘要校验保证下载与官方发布材料一致，不等同于独立的发行者数字签名。自带保底内核随应用整体打包；发行构建只有 ad-hoc 签名，不做公证。
- 解压使用路径清理和总大小/条目数限制，拒绝绝对路径、`..`、符号链接和非预期文件；只提取 frpc 与许可材料，不安装包里的 frps。
- 下载先写临时文件，可取消，取消/失败只清理临时内容；校验、架构及 `frpc --version` 检查成功后原子入库。自定义 frpc 明确显示“用户提供，未认证”，首次运行需用户主动选择。
- 切换内核先用目标二进制 verify 当前配置；成功后仅重启选中的连接。启动失败时恢复原版本一次，原内核不删除。
- 已下载内核不可变；应用更新带来的新版保底内核只用于新连接默认，不覆盖旧连接的固定版本。仍被引用的旧保底内核应在应用替换前复制到用户版本库并核验，避免更新后路径失效。
- 不能删除被配置、运行实例或回滚记录引用的版本。网络代理与 frpc 到 frps 的代理设置分开，不将下载网络设置混入隧道配置。

## 12. 发布、身份和外部依赖

本方案不运行打包、不生成密钥、不创建 GitHub 仓库或 Release、不申请 Apple 凭证。发布行为是以后单独执行的任务；不能把 build 当验证步骤。

正式发布前由项目所有者一次性确定：本产品公开 GitHub 仓库、最终 reverse-DNS Bundle ID、应用展示名称与更新签名密钥。当前 `com.example.frpc` 仅示例，不能带进首个公开版本。项目没有付费开发者团队，不申请 Apple Developer ID，发行构建只有 ad-hoc 签名，不做代码签名与公证。这些身份输入不影响先实施本地客户端逻辑；公开发版必须等这些值明确。

| 依赖/凭证                    | 用途与保存方式                                                               |
| ---------------------------- | ---------------------------------------------------------------------------- |
| MyGo v0.7.4                  | UI、平台 API、updater；保持 Go module 固定版本                               |
| frp 认证内核                 | 官方 frpc，随包保底，保留 Apache-2.0 许可材料                                |
| TOML Go 库                   | 使用 `github.com/pelletier/go-toml/v2`，实施时锁定版本；不手拼/正则修改 TOML |
| Go crypto / x/crypto scrypt  | 加密原文与备份；锁定依赖，敏感数据不交给网络服务                             |
| GitHub Releases              | 本产品应用发布，以及 frp 官方内核下载；公开客户端不嵌 PAT                    |
| `MYGO_UPDATER_PRIVATE_KEY`   | CI 产生更新签名，线下独立备份；公钥进入应用，私钥绝不进仓库                  |
| CI `GITHUB_TOKEN`            | 仅发布任务授予 contents:write，普通 check 无写权限                           |
| 用户 frps token/私密代理密钥 | 仅在客户端 `~/.frpc/config.json`（明文，0600）；由用户建连接时填写            |

GitHub、MyGo 官方文档和当前依赖源码在本次调研可读取；没有检查用户未来的发布仓库、Apple 账号或私钥。TOML/crypto 的具体锁定版本在实施的依赖变更中解析并记录，不采用未经核对的 API 写法。

未来发布流水线：CLI check 通过 → 另行授权的打包任务产出两架构安装包 → 生成签名更新资产 → 上传 draft Release → 检查两个架构的 manifest/资产完整 → 发布正式 Release。必须先上传完整资产再公开，不能让客户端看到缺包版本。更新签名与 Apple 代码签名是两套机制；本项目只保留更新签名，不启用 Apple 代码签名与公证。

不以关闭 Gatekeeper 或全局 `xattr -cr` 作为正常安装指导；未签名产物首次打开需用户在 Finder 中手动确认，这是未签名分发的已知限制，不宣称已解决安装信任问题。

## 13. 验证方案

严格遵守项目约束：只用 CLI check；不使用 Playwright、浏览器/原生 GUI 自动化，不运行 build；不创建 worktree。

直接依次执行以下检查：

```sh
gofmt -l main.go internal
go vet ./...
go tool mygo vet .
CGO_ENABLED=0 go test ./...
CGO_ENABLED=0 go test ./internal/ui/... -run Test -count=1
go test -race ./internal/app/... ./internal/runtime/... ./internal/storage/...
go test ./internal/config/... ./internal/runtime/... -run Integration -count=1
```

脚本要求 gofmt 输出为空，所有命令非零立即失败。`go tool mygo` 在 go.mod tool 声明落地后使用；race 仅覆盖不依赖 GUI 平台初始化的纯 Go 包，在支持的 runner 上运行，不将 `CGO_ENABLED=0` 强加给 race。

集成检查使用认证版 frpc 的 `verify`、内存 fake Admin API、伪子进程和固定版本 status 响应夹具。CI 中允许启动隔离在 loopback、随机端口的测试 frps，验证注册、重载与断线恢复；它只是一项测试依赖，不成为产品功能或分发内容。检查环境缺少内核时集成检查明确失败，不把 skip 计入通过。

| 层次      | 必测路径                                                                                                   |
| --------- | ---------------------------------------------------------------------------------------------------------- |
| 配置      | 各协议生成、IPv6、转义、端口边界、名称冲突、批量范围长度、未知字段/模板/includes 拒绝、敏感字段不泄露      |
| 仓储      | 原子写中断、磁盘满、revision 冲突、升级失败、损坏备份、跨版本恢复、密钥写入失败、加密包路径穿越/超限       |
| 进程      | 重复启动、启动后立即退出、Stop/Apply 竞争、父进程崩溃、旧 PID 复用、日志阻塞、超长行、停止超时、熔断       |
| API       | 认证失败、重定向拒绝、端口竞争、超时、坏 JSON、新字段、部分注册失败、空状态和过期响应                      |
| 应用变更  | verify 失败不改 active、reload 失败恢复、部分成功不自动撤回、回滚再次失败、更新 revision 不被旧结果覆盖    |
| UI Tester | 键盘与中文输入、列表重排不丢选择、sheet 草稿、焦点恢复、空/加载/错误/长文本/小窗口、窗口关闭后异步完成     |
| updater   | 开发模式禁用、无更新、离线、错误签名、取消、只读目录、重启确认、resume 一次性消费、固定内核迁移          |
| 内核      | 错架构、摘要不符、恶意归档、取消、被引用版本不能删、切换失败恢复、无网仍可用保底内核                       |

通过 `ui.NewTester` 在 900×600、1120×760 和 1440×900、明暗主题、文字缩放下检查布局边界及交互。CLI 结果能证明逻辑、布局约束和回归路径，不能证明真实 macOS Metal 呈现、输入法系统面板、VoiceOver 体验或分发包更新闭环；这些平台事实在未获准实际验收前明确标为未验证，不以 build 或静态检查替代。

## 14. 实施顺序与交付标准

以下是独立可用的增量，每一步都维持前一步可运行；不设置“先写一堆空框架，最后才连起来”的阶段。

### 阶段一：原生可用的最小客户端

迁移 Native UI 和 Go tool 配置；完成单连接、TCP/UDP、本地配置文件凭据、保底内核、verify、启动/停止、代理状态、日志、TOML 基础导入、关闭窗口继续运行、原生应用 updater 接入与 CLI 检查。正式签名更新需要第 12 节的发行身份，开发模式如实显示不可更新。

验收：从空数据创建 SSH 隧道，能注册，能显示端口冲突，能停止和重开窗口；错误不丢配置，退出无受管残留；CLI 检查通过。此阶段已是可用客户端。

### 阶段二：日常多连接工作流

增加并行连接、分组、搜索、HTTP/HTTPS、详情检查器、草稿和保存/应用事务、批量端口、菜单栏及登录启动设置。

验收：两个连接独立运行，停止一个不影响另一个；代理变更与公共参数变更的提示不同；部分注册失败能定位且不撤回其他成功隧道。

### 阶段三：高级客户端和数据可迁移

增加 STCP/SUDP/XTCP 与访问者、原文模式、内核版本库和切换、用户提供内核、加密备份/恢复、日志配额与诊断导出。

验收：私密代理两端能完成规定检查；错密钥和不支持版本可解释；内核切换失败恢复；备份恢复不覆盖现有连接或自动连接。

### 阶段四：首个正式发行

补齐两架构检查、未签名产物的首次打开与更新替换验证、真实 GitHub Release 更新资产和应用/内核版本迁移验证；所有发布操作在后续明确授权范围内执行。

验收：旧版可发现新版本并验证签名；用户推迟更新时连接不受影响；重启后固定内核与凭证保留；更新失败有明确恢复路径。若仍仅获准 CLI 检查，应保留未完成的平台体验验收项，不宣称已完成完整发行验证。

工作量预估：熟悉 Go 的单人专职开发，阶段一约 5–8 个工作日，阶段二约 5–8 日，阶段三约 7–10 日，阶段四约 3–5 日，总计约 4–6 周；不含等待 GitHub 仓库与发布授权等外部时间。这是排期估计，MyGo 边缘问题和跨版本 frpc 适配是主要波动来源。

## 15. 风险、降级与回退

| 风险                        | 处理方式                                      | 可接受的降级                                              |
| --------------------------- | --------------------------------------------- | --------------------------------------------------------- |
| MyGo 自绘与 AppKit 细节不同 | 内建组件优先，稳定 ID、线程规则和 Tester 检查 | 保留传统标题栏与实色背景；不能换成 WebView 冒充 Native UI |
| 管理 API/日志在内核间漂移   | 固定认证版本和适配器，不导入 frp 内部 Go API  | 原文运行、未知状态、需重启，显式标记                      |
| GitHub 离线/限流            | 本地缓存、延迟重试、请求合并                  | 旧内核继续运行，保底内核可离线使用                        |
| 配置文件不可写              | 停止需要凭证的操作并提示检查权限              | 保留内存中的编辑，不删除已保存配置                        |
| 配置热重载部分失败          | 区分配置被接受与代理注册结果                  | 保留成功条目，对失败对象单独处理                          |
| 应用崩溃留进程              | 管道看护 + 启动身份核对                       | 身份不明时由用户处理，不批量杀进程                        |
| 更新中断连接                | 运行中不自动重启、一次性 resume               | 提醒用户稍后更新，原内核保持固定                          |
| 方向不合适需要撤回          | 阶段化、文件备份、内核不可变                  | 不删除用户原始配置；公开版本回退配套 schema 备份          |

最脆弱的前提是：MyGo 0.7.4 能覆盖该工具所需的 macOS 输入、列表、辅助功能与窗口体验。本文用系统集成、内建控件和可独立交付的最小客户端降低风险，但 CLI 检查无法证明全部平台体验。若后续实际使用暴露框架缺陷，先缩减自定义控件并修复/上报 MyGo；若需求变为“必须是 AppKit 控件”，则需要用户重新决定 UI 栈。
