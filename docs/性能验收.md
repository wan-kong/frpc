# CLI 性能验收

此入口对应技术方案 10.2 的持续负载部分，不替代 macOS 实际呈现、进程启动至系统窗口可输入的延迟、空闲 CPU 或发行包验收。全程只使用 CLI check，不执行 build、浏览器或原生 GUI 自动化。

## 运行

```sh
FRP_SOAK_DURATION=30m CGO_ENABLED=0 go test ./internal/acceptance -run '^TestPerformanceSoak$' -count=1 -timeout=45m -v
```

默认运行真实时间 30 分钟，另外需要数秒准备及退出。需要先自行将摘要校验过的官方测试 frps 放到 `.test-tools/frps`；缺失时用例跳过。数据、端口、内核目录均独立于用户数据；测试 frps 只监听 loopback。所有测试进程由用例负责清理，不操作已经运行的用户应用。

需要验证入口本身时可以使用：

```sh
FRP_SOAK_DURATION=30s CGO_ENABLED=0 go test ./internal/acceptance -run '^TestPerformanceSoak$' -count=1 -timeout=5m -v
```

短时结果标记 `smoke-passed`，不会标记完整通过。30 分钟及以上才可能得到 `full-cli-passed`，任一检查失败均返回非零并记录 `failed`。日常 Go 检查不执行长时用例，不将 opt-in 跳过计为性能通过。

## 实际负载与测量边界

- 20 份持久化连接，每份 25 条 TCP 隧道，共 500 条配置；其中 10 个真实 frpc 同时运行，250 条隧道必须持续注册成功。定期通过每个运行连接的真实远程端口做 TCP 回显。
- 使用 0.72.0 保底 frpc 和官方测试 frps；通过生产 Controller、Supervisor 和看护子进程启动，不用 fake Admin API 冒充运行连接。
- 每 100ms 生成 10 行含中文和敏感字段的合成日志，经过生产 `logging.Buffer.Read`、脱敏、内存配额和磁盘轮转。仅在 Tester 中替换当前连接日志快照，以复现精确负载；不声称这些日志由 frpc 自身产生。每轮检查行数、字节上限和已知敏感值是否泄露。
- 使用完整应用 View 和 `ui.NewTester`，1120×760 DIP。每 100ms 刷新快照及帧，交替查看全部 500 条配置与当前连接；每秒发送搜索快捷键、全选、删除、输入事件并确认控件值变化。
- `frames` 是每个渲染步推进到期动画并调用 Tester 完整帧的墙钟耗时，包含软件光栅化及可能到期的额外帧，比单纯布局耗时范围更广；不是 Metal 帧率。`inputs` 分别测量一次键盘/文本事件到控件反馈，`inputSequences` 另行保留聚焦、全选、删除、输入的整组耗时；不能证明系统输入法延迟。`firstHeadlessFrameMs` 只记录 View 首帧，不冒称应用冷启动。
- 每分钟强制 GC 后采集保留堆，使用 `ps` 分别记录验收主进程和 10 个 frpc 的 RSS/CPU；不将 frpc 或测试 frps 的内存算进主进程。`ps` 的 CPU 数值为系统采样值，不能当作整个区间的精确 CPU 时间。
- CPU profile 覆盖负载阶段；GC、资源采样和网络回显不计入帧及 UI 更新的耗时样本。

## 检查标准与产物

帧 p95 ≤16ms，UI 快照更新及搜索反馈 p95 ≤50ms，受管进程退出 ≤5s。日志应达到 100 行/秒，允许 1% 调度误差及结束边界尚未完成的一批 10 行。持续检查所有运行隧道注册状态和真实回显，失效立即失败。

完整时长下，比较五分钟暖机后的保留堆：结束值不得比基线增长超过 16MiB，线性拟合增长不得超过 256KiB/分钟。这是对内存趋势的明确检测阈值，报告保留所有原始采样，不能将通过解释为数学意义上的无泄漏证明。

最终采样在 GC 后通过 `runtime.KeepAlive` 保持 View、Tester 及采样数组存活，避免编译器因后续不再访问对象而提前释放它们，造成终态堆显著低估。

报告保存在 `.test-tools/performance/<UTC时间>-<进程号>.json`，CPU profile 为同名 `.json.cpu.pprof`。报告每分钟更新，状态为 `running`；只有进程终止后的最终报告和 exit code 能证明通过，不能凭文件存在判定完成。

新生成的报告包含启动时的 `sourceSha256`（main.go、Go module 文件、mygo.json 及 internal 下的 Go 源文件）、`coreSha256` 和请求时长。变更后的代码必须有相应验收证据，不能把旧版本的长时结果直接认作新 UI 的通过结果。进行中的报告也会更新当前注册数量与实际日志速率。

```sh
go tool pprof -top .test-tools/performance/<报告名>.json.cpu.pprof
```

首窗口启动 p95、真实 Metal 呈现、VoiceOver、Intel 实机和签名更新闭环仍需各自的验收证据，本入口不覆盖。
