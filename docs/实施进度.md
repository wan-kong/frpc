## 与原方案的有据调整

1. MyGo 自带 Native updater 插件没有暴露本产品所需的重启协调钩子，因此直接调用 `mygo.Updater` 引擎，只保留一个薄 Native UI 检查/安装面板；自建更新状态机、后台轮询、跳过版本和更新偏好已移除。没有引入 WebView 或另一套更新签名机制。
2. 保底 frpc 以 gzip 资源保存，避免发行签名流程修改 Mach-O 后使固定摘要失效；运行时从受应用资源签名保护的压缩文件解压并核验原始官方内核。
3. 残留进程默认阻止重复启动。连接设置提供身份审查；明确展示 PID、启动时间、受管内核和配置后，用户可选择停止/强制终止，执行前复核记录摘要与身份。身份不明不发送信号，不按名称或旧 PID 批量杀进程。
4. 快照仍引用的凭证会保留到最后一个有效引用消失，避免回收区到期后破坏保留的快照；配置回收区在启动时执行七天期限清理。

### 命令契约收尾

- 连接修改操作统一通过 `Execute`，多连接批量操作通过 `ExecuteMany`，并发上限为 4。UI 和菜单栏在用户意图形成时捕获 operationID 与期望 revision；保存并应用在同一个连接范围内串行执行，移动同时检查源和目标版本。
- 相同 operationID 与相同请求在本次会话内等待或重放原结果；不同内容复用同一 ID 返回 Conflict。请求用会话密钥 HMAC 绑定，包括不参与普通 JSON 序列化的 metadata。回执不保留请求原文、凭证或成功状态快照，每次回复提供当前的新快照；失败和已保存但应用失败的结果也可稳定重放。
- 设置、内核目录、备份恢复/导出、CA 导入及首次隐藏确认统一通过 `ExecuteGlobal`。设置和内核目录分别维护 revision，连接编辑不会制造无关冲突；隐藏提示确认是单调 patch，不会被旧设置草稿撤销。
- 内核下载、检查和 staging 在目录提交锁外执行；登记前复核文件与目录 revision，拒绝过期提交。检查覆盖网络准备被阻塞期间，连接停止和设置保存仍可完成。
- 备份恢复重放返回相同的新建连接 IDs，不再创建重复连接；备份导出重放不覆盖用户随后修改的文件。兼容入口仍通过相同命令边界执行。
